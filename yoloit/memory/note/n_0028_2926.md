# Note: n_0028_2926

Mixed old/new TUI frames after yoloit board switch (fixed 2026-10-26, yoxterm 67474ad / yoloit aff69ca3): remounting TerminalView re-fires RenderTerminal._resizeTerminalIfNeeded with UNCHANGED cell dims (200ms alt-buffer debounce still calls terminal.resize). Terminal.resize used to run its full body even for same dims — resetting DECSTBM vertical scroll margins on BOTH buffers, clearing alt scrollback, clamping cursor. PTY sees no size change → no SIGWINCH → differential alt-buffer TUI (Fa) never full-redraws and keeps writing into a grid whose scroll region silently reverted to full-screen → old/new frames interleaved forever; manual resize cured it via SIGWINCH. Fix: Terminal.resize early-returns when cols/rows unchanged, onResize still fires for backend re-sync; real resizes keep legacy margin reset. Custom-font transient (default 13pt first frame until async SessionPrefs load) is coalesced by the existing 200ms alt debounce and never reaches the grid — no extra fix needed (covered by test). Lesson: emulator-state mutations must be tied to ACTUAL dimension changes, not to view (re)attach; DECSTBM margins are TUI-owned state whose silent reset desynchronizes differential renderers.
