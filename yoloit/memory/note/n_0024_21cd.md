# Note: n_0024_21cd

Flutter pointer-wheel routing gotcha (yoloit terminal bug 2026-10-25): Scrollable._receivedPointerSignal registers with pointerSignalResolver only if physics.shouldAcceptUserOffset AND the scroll would actually move the position (interest gate). A Scrollable parked at a zero-height scroll range still passes the interest gate for one wheel direction and WINS the resolver (first-registration-wins, hit path leaf-first) — swallowing the wheel for shallower consumers. Fix pattern: give the dead-end Scrollable NeverScrollableScrollPhysics (fails physics gate, no registration). In yoxterm this applies to TerminalView's inner scrollback Scrollable while the terminal is in the alt buffer (TUI mode) — the outer InfiniteScrollView (TerminalScrollGestureHandler) must own the wheel to encode mouse reports. Terminal/useAltBuffer() does NOT notify listeners — alt-buffer transitions only notify via the escape-sequence parser path, so tests must enter alt mode with terminal.write('\x1b[?1049h'), not by calling useAltBuffer() directly. Also: never notify ChangeNotifiers synchronously from dispose() — during board-switch unmount sweeps the tree is locked and listeners (ValueListenableBuilder) throw 'setState when widget tree was locked' (CanvasInteractionLock defers lockStateVersion notify to a microtask).
