# Note: n_0025_e56d

Terminal viewport glitch after yoloit board switch (fixed 2026-10-26, yoxterm 75dcc2f / yoloit a3c709c8, local-only): board switch fully unmounts TerminalView; on remount yoxterm RenderTerminal hardcoded _stickToBottom=true and its first performLayout correctBy'd the viewport to maxScrollExtent, overriding ScrollController.initialScrollOffset — the host only had a post-frame jump back (one-frame bottom flash) and its restore heuristic treated offset≈0 as "unset→bottom", so a user parked at the TOP of scrollback permanently lost position. Fix pattern: yoxterm TerminalView.snapToBottomOnAttach (default true = legacy follow); pass false + seed ScrollController(initialScrollOffset: persisted) when the user has scrolled — yoloit tracks it via AgentSession.hasUserScrolled (set in the scroll-persist listener, kept out of Equatable props). Testing gotcha: pumpWidget with an identical tree shape REUSES TerminalView state and its ScrollPosition (new controller's initialScrollOffset ignored) — pump an interstitial widget (e.g. SizedBox) between mounts to simulate real remounts. Correct-by (ScrollPosition.correctBy/correctPixels) is SILENT — it does not fire ScrollController listeners, so a snap-induced offset change does not mark hasUserScrolled.
