# Note: n_0026_3931

quickjs_runtime (IstiN/quickjs_runtime) ubuntu CI flake root-caused & fixed in 0.4.8 (commit 0355922): the "isolate race" was NOT a QuickJS data race. The Dart VM migrates an isolate between OS threads once it is not pinned inside an FFI call; QuickJS anchors its stack-overflow limit (rt->stack_top - stack_size) to the thread that CREATED the runtime (JS_NewRuntime → JS_UpdateStackTop). An eval on a migrated thread spuriously fails at parse time with SyntaxError("stack overflow"); rendering that error overflows again → JS_ToCString returns NULL → silent undefined/null eval result. Fix: bridge calls JS_UpdateStackTop(JS_GetRuntime(ctx)) at every JS entry (qjs_eval, qjs_execute_pending_jobs[_capped]) — race-free due to the pool's one-runtime-per-isolate discipline. Diagnostic recipe that cracked it (local mac + arm64/x64 docker containers NEVER reproduce; flake was ~100% on GitHub ubuntu-latest only): pushed a debug branch with stderr instrumentation in qjs_eval (log undefined completions, exceptions, and probe err.name/message/stack when JS_ToCString returns NULL) + workflow on '**' branches; the wedged exception printed name=SyntaxError message=stack overflow at eval depth 0. TSAN build of the bridge found zero C-level races — don't waste time there. Also: gh run rerun / workflow_dispatch need admin rights on IstiN repos; repo convention allows empty `ci: retrigger` commits on main. gh api .../actions/jobs/<id>/logs --allow-escape-sequences fetches runner logs.
